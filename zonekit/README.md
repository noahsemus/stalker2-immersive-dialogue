# Zone Kit (pak) port — feasibility notes

Branch `pak-mod-experiment`. Goal: ship ImmersiveDialogue as an official Zone Kit
pak mod with no UE4SS dependency. Nothing here touches the shipped DLL on `main`.

## What the Zone Kit can do (verified 2026-09-13 against the installed kit)

- **Asset overrides are an official feature.** Content Browser → right-click a game
  asset → *Checkout selected content to mod plugin folder* copies it into
  `Stalker2\Mods\<Mod>\Content\<same relative path>`. The cook classifies such
  packages as *overrides* (`SavedMods\PackageClassifier\<Mod>\OverridePackages.txt`)
  and ships them in `<Mod>Stalker2-Windows-OverrideContent.pak/.ucas/.utoc`.
  Noah's installed ZoneWatch mod uses exactly this and loads in the retail game.
- **Actor class replacement.** For Blueprint actors the kit auto-generates
  `Autogenerated_*_ActorReplacementData.uasset` mapping the game class to the mod
  class; `ModActorReplacementSubsystem` swaps spawns at runtime. The existing
  `Stalker2\Mods\ImmersiveDialogue` project already has a checked-out copy of the
  player pawn Blueprint (`/Game/GameLite/Blueprints/Characters/Player/BP_Stalker2Character`,
  parent `/Script/Stalker2.PC`) plus its replacement asset (Sep 9). It was never
  cooked into the installed pak, so it is untested in-game.
- **Config overrides** (`CoreVariables.cfg` etc.) — already proven by the
  No Dialogue Zoom paks.
- **Cook/pak commands** (from `GSCModdingUtils.Automation.dll`):
  `GSCCookModNewContent`, `GSCCookModOverrideContent` (`-CustomConfig=ModCookNewContent|ModCookOverrideContent`),
  `GSCCreatePlainMod`. `PakPlainMod.bat` passes `-skipcook -skipiostore`, so it
  only ships loose files (cfg). Cooked assets need the editor's *Package Mod* (or
  the UAT command without the skip flags).
- **Editor Python** (3.11) is available; remote execution over UDP/TCP is off by
  default. `scratch ue_exec.py` drives the running editor once enabled
  (Editor Preferences → Plugins → Python → Enable Remote Execution).

## Relevant game assets (names confirmed in the pak index)

- Input: `/Game/_Stalker_2/data/input/InputMappingContexts/` — `IMC_Exploration`
  (normal play), `IMC_Dialog`, `IMC_DialogOnTheGo`, `IMC_NoInput`, `IMC_Cutscene`…
  `/Game/_Stalker_2/data/input/InputActions/` — `IA_LookUp`, `IA_Walk`,
  `IA_LocomotionForward`, `IA_UI_Dialog_SelectAnswer`, `IA_UI_Dialog_AnswerConfirm`…
  `DefaultInput.ini` also still carries legacy axis mappings (`Forward`, `Right`,
  `Turn`, `LookUp`) — which path the pawn actually consumes is open.
- Player: `BP_Stalker2Character` (Blueprint; graph already references
  `IsInStaticDialog` and `PlayDialogGesture`), `AnimBP_Player`, `AnimBP_Player_Shadow`.
- Dialogue UI: `/Game/GameLite/FPS_Game/UIRemaster/Dialogue/W_DialogueView`.
- Native only (no Blueprint graph): `CameraModifier_LookAt`, `PC`,
  `Stalker2PlayerController`, `PlayerEnhancedInputComponent`.

## Feature-by-feature mapping

| DLL feature | Pak approach | Confidence |
|---|---|---|
| Left stick scrolls answers | Override `IMC_Dialog`: delete the two `Gamepad_LeftStick_Up/Down` → `IA_UI_Dialog_SelectAnswer` rows | certain |
| Move + look in dialogue | (a) add the exploration move/look mappings to `IMC_Dialog`; if the native `PC` handler gates on dialog state, (b) poll keys in the `BP_Stalker2Character` override on Tick and call `AddMovementInput` / `AddControllerYawInput` | experiment |
| Camera centering off | In the BP override: `PlayerCameraManager → FindCameraModifierByClass(CameraModifier_LookAt) → DisableModifier` each tick in dialog | likely |
| Strafe body drag (`bOrientRotationToMovement`) | Set on `CharacterMovement` in the BP override during dialog | likely |
| Walk animation in dialogue | Override `AnimBP_Player` and remove the dialog gate in the graph instead of per-tick struct writes | likely, larger compat surface |
| Gesture camera swing | `SetAbsolute` + per-tick relative rotation is reproducible in BP; the head-bone detector too | medium |
| `IsInStaticDialog` lie hook | not reproducible; covered by the AnimBP edit above | — |
| Sensitivity from `AppliedSettingsWin64.cfg` | not needed — the game's own input pipeline applies it | — |

## The decisive experiment

Override `IMC_Dialog` only (remove left-stick rows, add move/look rows copied from
`IMC_Exploration`), cook, install to `~mods`, talk to an NPC. If Skif walks, the
whole mod can be a pak. If not, the BP-tick polling fallback is the next test.

## Costs

- Overrides of `BP_Stalker2Character` / `AnimBP_Player` conflict with any other
  mod overriding those assets. `IMC_Dialog` and cfg overrides are low-conflict.
- Every game update requires re-cooking against the new Zone Kit build.
